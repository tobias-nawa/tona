## Plan

Why now: the scale run is due every three days (`docs/contribute/measurement.md`); the last one is `2026-11-05-scale-run.md` (build
7bb06d2, follow-ups to 11-06). Since then only comments and text changed in the engine (release clean-up; `scripts/isa-diff.py`:
all kernels identical), plus the GPU-lock default `work/gpu.lock` (`TONA_GPU_LOCK`; `/var/tmp/claude/gpu.lock` is a symlink to
it). The run is also the release measurement (#43): block g (ClassLRU, #98) runs in any case unless a GPU fault, hang or
oom-kill stops it (it was postponed three times), and block i compares with llama.cpp for the release result table.

R8 (block e) checks #103 a second time: is the evicted time under page-cache pressure still below 1 s per pressured request
(11-05: mean 2.08 s, corrected from 0.05 s; 11-03: mean 4.78 s)?

One build: `work/build/merged`, built fresh in this run from a5a5d37 (`cmake -S engine -B work/build/merged`, the worktree
a separate worktree, branch `scale-run-1110`, `work/` is a symlink to the main checkout);
`scripts/build-fresh.sh` passes. Nothing is built after the run starts. Drivers: copies of the 11-05 drivers in
`/var/tmp/claude/scale1110/` (`curve.py`, `drive.py`, `run.sh`, `master.sh`, new `i.sh`); changes: paths to scale1110, the lock
path of `run.sh` is `work/gpu.lock`, `master.sh` writes the desktop VRAM (no engine running) before each block and the
expert-slot count of every server start into its log. The needle drivers are not used (blocks h1 to h3 were done on 11-05).
Every server runs in a `systemd-run --user --scope` with `MemoryMax=54G`, `MemorySwapMax=0`, port 8097, under the GPU lock.
No other worker measures (another worker reads tickets only).

**Desktop VRAM before the start.** Long **prefill** depends on the free VRAM through the expert slot count (11-05: desktop
1.4 to 2.45 GB over a night, 59 instead of 71 slots at 1M, 1M **prefill** 1,018 instead of 1,127 tok/s). The start needs at
most 1.5 GB desktop VRAM without an engine; the value is written per block.
