# Prefill workspace as extra expert slots (#36), 2026-11-02

Rule 2 plan, written before the first run on the branch `36-pf-slots` (main 40a09c5). Results are read against it
below the line `## Results`.

## Plan

Mechanism: the workspace of the chunk-by-chunk prefill (912 MB for chunks of 2,048 tokens) lies behind the expert
slots in the same allocation. Between prefills its memory holds extra slots of the expert cache (same count in every
layer, in two ranks, from the top of the workspace downwards). A chunk-by-chunk prefill gives up the blocks that start
below the bytes it uses (`prefill_arena_bytes(chunk)`); the chunk of a prompt up to 2,048 tokens shrinks to its
size, so a short prompt takes little. The layered prefill (more than one chunk) does not use the workspace and takes
nothing. `IE_PF_EXTRA_SLOTS=0` switches it off (baseline arm, also the exit if it misbehaves in service).

1. Scope
   - R1 `ctest -L unit` (new `mega_extra` test: layout on the slot grid, eviction by overlap, restore).
   - R3 mini golden (`GOLDEN_MODEL=mini`, gpu and cpu plan, server) then the big golden checks of
     `tools/select_checks.py` through `scripts/gpu-status.sh --own --build work/build/w36` (gpu, cpu plan, prefill,
     prefill dflash, server). The tokens must be identical to the recorded references (`IE_DETERMINISTIC=1`): an extra
     slot changes hits, not numbers. The goldens use the extras (the big model has about 84 base slots); the mini
     model has all experts in slots and so tests nothing here.
   - Forced test: server, two requests of one conversation with a chunk-by-chunk prefill between the decodes, with and
     without `IE_PF_EXTRA_SLOTS=0`; the tokens must be equal (the extras are evicted, used, restored).
   - R5 `scripts/ab.py --a main --b w36 --workload short,set`: A = main 40a09c5, B = this branch, `IE_DIAG=1` in
     both. `short` (2 requests, 2K prompts = chunk-by-chunk prefill of a full chunk, 400 tokens decode) and `set`
     (14 requests, up to 400 tokens). Rounds as `ab.py` decides (`bench/noise.toml` has decode@2000 with sd 0.23 %,
     `decode-code` for set), at most six.
   - Counters first (docs/contribute/measurement.md principle 3): hits and misses per request from `/status` (`expert_hits`,
     `expert_misses`) and the new `early_hits`/`early_misses` (the first 10 target passes after a prefill, to see
     what giving up the extras costs). One run per arm gives them before any rate is read.
   - Extras left after a prefill: `IE_VRAM_LOG=1` prints the layout (slots per layer, MB used); `IE_PF_DEBUG=1`
     prints, per prefill, how many extra slots it gave up.
   - GPU time: goldens about 6 min plus mini about 2 min, forced test about 3 min, ab about 15 to 40 min.
   - Why this size: the cost of giving up the extras is paid per turn, so `short` (a prefill per request) and `set`
     (many turns) are the workloads that show it; `long` and `mid` use the layered prefill, which is unchanged.
2. Expectation (sources: `2026-10-25-slots.md`: +0.14 % decode per slot; `tools/cache_sim` on traces trp1 and trp2 with
   `--server-fill`, scratch `/var/tmp/claude/w36/alloc.py`)
   - Slots: 446 extra slots of the 912 MB (9.3 per layer) minus alignment (two ranks, up to one slot per block): about 8
     to 9 per layer. Base about 84 at ctx 140000.
   - Hit rate over the unions: 88.24 and 86.99 % (LRU, 84 slots) rise to 89.96 and 88.85 % with 9 more
     (+1.7 to +1.9 points); with ClassLRU +1.6 to +1.8 points. At the full extras, so only after refilling.
   - Decode: +1.3 % for the full 9 slots (2026-10-25-slots), after the refill; tolerance +1.0 to +1.6 %. A full chunk
     takes all extras every turn and the server fills 4 per layer and pass, so the first few passes after a turn run
     with the base slots: expect `early_hits` at the rate of today and the later passes above it.
   - Prefill (rate of the prompt): equal within noise (the chunk of a short prompt is smaller, 128-token tiles
     unchanged). A prefill that takes the whole workspace (2K prompts) refills the extras afterwards through misses.
   - Tokens: identical.
3. Active tooling: `IE_DIAG=1` in all GPU scripts, `IE_VRAM_LOG=1` in the first start of each arm, `IE_DETERMINISTIC=1`
   in the goldens only (not in the speed arms), 60 s between blocks, no build during a measurement, GPU lock for every
   run and build.

## Results

Builds: A = `merged` (main edaf13c, includes #81), B = `w36` (branch 36-pf-slots rebased on it, 9142be7). The first
attempt compared against 40a09c5; main moved on (#81) while it waited for the GPU lock, so the branch was rebased and
all numbers below are from the rebased build. Raw data and per-round reports: `work/ab/w36-*.md` and `.json`.

### Layout on the big model (`IE_VRAM_LOG=1`, `--ctx 140000`)

- 84 base slots, workspace 807 MB (not 912 MB: the figure of the ticket was for the old chunk). The extra slots first
  took the same number for every layer: 6 per layer, 589 of 807 MB, because the alignment of the 96 blocks to the slot
  grid eats about 1 MB each and 7 did not fit. One more slot for each layer in turn while it fits: 7 per layer
  (about 330 slots in all), 676 of 807 MB.
- Slots given up (`IE_PF_DEBUG=1`), chunk by chunk: 158 tokens (chunk 256) 63 slots; 366 tokens (chunk 384) 81;
  964 tokens (chunk 1024) 175; prompts above 2,048 tokens go layer by layer and give up none.

### Counters (deterministic, `/status`)

|---|---|---|---|
| `short` request 2000 | 131,811 / 19,885 | 134,222 / 17,474 | 86.89 % to 88.48 % (misses -12.1 %) |

The simulation (`tools/cache_sim`, LRU, 84 slots, 9 more) expected +1.7 to +1.9 points; 7 slots measured +1.6 to
+2.5 points. Hits in the first 10 target passes after a prefill (`early_*`): 81.72 % to 84.26 % (+2.54 points); later
passes 87.04 % to 88.52 % (+1.48). So giving up the extras costs nothing visible: even the first passes after a turn
profit, because a short turn takes only part of them.

Reading against the plan:
- Decode: +0.8 to +1.2 % on the three metrics with a clear decision, inside the planned +0.8 to +1.8 % (the planned
  +1.0 to +1.6 % was for 9 full slots; the layout gives 7 and a part of them is out of use after a turn). `decode-text`
  is the finding: +0.45 % [-0.61, +1.52] after 6 rounds, not decided and not negative.
- Prefill: the first run left the prefill open at -0.96 % because of two outlier rounds (-3.73 % and -1.55 %, both in the
  order AB; the cause is not known). The two follow-up runs with 8 fixed rounds
  give +0.05 % and +0.16 % with the extra slots and +0.5 % without: no loss of prefill. The 300-token prefill is
  +0.55 % faster because its chunk is 384 instead of 2,048.
- Tokens: identical (SHAs in every run; `IE_DETERMINISTIC=1` goldens and `scripts/extra-slots-check.sh` below).
