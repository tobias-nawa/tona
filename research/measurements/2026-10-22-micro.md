## Assessment (by hand, 2026-10-22)

Own measurement, 7 repetitions. RAM still the old 32 GB kit (2× 16 GB, EXPO 6000).
HIP reports "16 CUs" as `multiProcessorCount`; those are 16 WGPs = 32 CUs.

**Methodology checked:**

- Zeros and random data read equally fast (316 GB/s): compression does not distort anything.
- A first run with a grid 4× too large showed ~900 GB/s at 64–128 MiB. Cause: only a quarter
  of the blocks were resident, each ran its passes over part of the buffer, and that
  part fit in the Infinity Cache. Fixed, grid = resident blocks (128).
- VRAM bandwidth cross-checked with `rocprofv3 --kernel-trace`: 13.6 ms for 4 GiB = 316 GB/s.

**What the numbers mean for the engine:**

| Quantity | measured | assumed before | Consequence |
|---|---:|---:|---|
| VRAM read | **315 GB/s** | 320 GB/s (datasheet) | 98 % of 1258 MHz × 16 × 128 bit = 322 GB/s. The decode ceiling from research/03-feasibility.md holds |
| Infinity Cache (8–32 MiB) | **~1.18 TB/s** | – | 3.7× VRAM. What is read several times per pass and is ≤ 32 MiB belongs there |
| L2 (≤ 4 MiB) | **~3.6–4.1 TB/s** | – | |
| PCIe per direction | **55.7 GB/s** | ~50 GB/s | 88 % of 63 GB/s. Pageable is barely slower at 1 GiB (55.4) |
| PCIe both directions together | **60.8 GB/s** | ~100 GB/s | **not true duplex.** Uploading experts and downloading KV share ~61 GB/s |
| PCIe 64 KiB blocks | 11.6 GB/s | – | small copies are expensive, batch experts |
| Kernels back to back | **2.1 µs/kernel** | – | ~500 kernels per decode pass ≈ 1 ms of a ~10.5 ms budget |
| HIP Graph | **2.08 µs/kernel** | – | **gains nothing here** over normal launches. Fewer kernels only via fusion/megakernel |
| Launch + sync (round trip) | **17.7 µs** | – | one CPU-GPU synchronization per layer costs 48 × 18 µs ≈ 0.85 ms per pass |
| WMMA f16 → f32 | **93 TFLOPS** | 51.3 (datasheet = vector FP16) | matrix rate is twice the datasheet |
| WMMA bf16 → f32 | **97 TFLOPS** | – | |
| WMMA fp8 → f32 | **186 TFLOPS** | – | 2× f16, confirms the FP8 path for prefill |
| WMMA int8 → i32 | **183 TOPS** | – | same as fp8 |
| WMMA int4 (K=32) | **341 TOPS** | – | |
| FMA f32 | 24.3 TFLOPS | 25.6 | 95 % |
| RAM read (CPU) | **58 GB/s**, already with 1 thread | ~64 GB/s | fabric limit of the single CCD. More threads do not help |
| RAM write (CPU, stream) | **31 GB/s** | – | half the read width of the fabric link |

**Prefill:** it is compute-bound; the ceiling is the measured WMMA peak (93 TFLOPS f16, 186 TFLOPS fp8).

**Decode:** launch cost and synchronization together ~1.9 ms per pass, i.e. ~18 % of the budget at
95 passes/s. HIP Graphs do not solve this on this stack.

**Open:** persistent kernel (latency of a grid sync), comparison ROCm 7.1.1 against 10.1,
repeat the RAM values with the 64 GB kit.
