# 2026-10-23: Forward pass version 2, megakernel

Own measurement. `engine/gpu/mega.hip`, tool `ie-gpu-gen --mega`. RAM 32 GB, DPM `auto`, desktop on the
same GPU. Prompt: chat format "parse CSV, column means, code only", 33 tokens.

## Setup

- 860 steps (ops) per token in 49 segments: one kernel launch per segment between two routers
  (before ~4,000 kernels per token). Top-k of the experts and reloading on the CPU between the segments.
- All blocks work through every step together, own grid barrier with a time limit in between.
- Small steps merged: norm with combine (every block computes the group sums itself),
  mix with int8 rounding, DeltaNet conv with L2 norm, recurrence with norm, σ(z) and int8, attention with σ(gate)
  and int8, SiLU as epilogue of the gated-residual down.
- Matvecs via the int8 path (BF16 and Q2_0 float). 162 VGPRs, 32 KB LDS per block.

## Correctness

- float matvecs (`IE_MEGA_F32=1`) against the CPU reference: 6 steps, top-1 equal, logits ≤ 4.0e-7 relative.
- int8 against the CPU reference: 10 steps, top-1 equal in 9 (one close call), largest deviation 0.21 relative.
- Teacher forcing, 1,363 tokens of Python:

  | | NLL | Perplexity | Top-1 |
  |---|---:|---:|---:|
  | Version 1, float | 0.8225 | 2.276 | 82.2 % |
  | Version 2, int8 | 0.8212 | 2.273 | 81.9 % |

## Blocks, waves and deadlock

HIP reports 16 "multiprocessors" (WGPs of 2 CUs each). Measurement mode without reloading, 200 tokens:

| Blocks × waves | Waves total | tok/s (decode) | Barrier aborts |
|---|---:|---:|---:|
| 48 × 8 | 384 | – | **Deadlock** in 2 of 2 runs, also with a 3 s time limit |
| 40 × 8 | 320 | 32.6 | 1 of 2 runs |
| 32 × 8 | 256 | 32.9 | 0 |
| 16 × 16 | 256 | 29.7 | 0 |
| 24 × 16 | 384 | 33.4 | 0 |
| **32 × 16** | 512 | **35.4** | 0 |

Interpretation: with 32 KB LDS, 2 blocks of 8 waves fill the LDS of one CU. If the desktop occupies something there, the
second block does not fit, and all others wait at the barrier for it. One block per CU (32 × 16) does not have this
problem. **Endurance test: 1,000 tokens, 2 runs per variant, 101,234 launches, 0 aborts** (32 × 16: 33.4 tok/s,
32 × 8: 30.8 tok/s). Default: 32 × 16.

## Speed

| | Version 1 (single kernels, float) | Version 2 (megakernel, int8) |
|---|---:|---:|
| without reloading, 200 tokens, 3 runs | 27.4–27.6 tok/s (decode) | **35.4 tok/s (decode)** |
| teacher forcing with reloading, 1,363 tokens | 13.1 tok/s | 11.7 tok/s |

With reloading version 2 is slower: missing experts are read by the CPU (pread) while the GPU waits, because the
segment only starts when all experts are there. Version 1 computes the hits in the meantime. With 32 GB RAM the
page cache does not fit all experts, reloading determines the time.

## Next steps

1. Overlap reloading: hits and shared expert first, misses wait in the kernel for a marker of the
   copy stream.
2. Measure the time per step in the kernel (timestamps at the barriers), then optimize in a targeted way.
3. Make the token repeatable (DeltaNet state doubled, ring buffer with one more place): if the
   barrier aborts, recompute the token instead of aborting.

## Addendum: one kernel per token

Instead of 49 launches (the CPU waits for the kernel to end after every router) the whole token runs in one kernel.
At the router, block 0 writes the 256 logits into a mailbox (host memory, coherent), sets a marker and
waits; the CPU picks the experts, reads misses by pread into a mapped buffer and sets its marker;
all blocks copy the misses over PCIe into their slots. 1,040 steps.

| | tok/s (decode) without reloading, 200 tokens, 3 runs |
|---|---:|
| one launch per segment (IE_MEGA_SEGMENTS=1) | 39.63–39.64 |
| one kernel, system-wide fence in all threads | 38.3–38.7 (fence 1.8 ms per token: writes back the L2) |
| one kernel, fence only in block 0 | **41.4–41.7** |

Mailbox 7.5 µs per router (358 µs per token), copying 82 µs per token (measurement mode: no misses).

With reloading (300 tokens, 24.2 GB reloaded, page cache too small at 32 GB RAM):
one kernel 18.9 / 24.5 tok/s (decode), segments 17.1 / 17.7 tok/s (decode). Very noisy, conclusions only with 64 GB.

## Addendum: hyper-connections as Q8_0

hc_attn/ffn down and up (BF16, 4 × 6.55 MB per layer, 1.28 GB per token) converted to Q8_0 at load time
(blocks of 32, f16 scale, like ggml); x as int8 for that: COMBINE_NORM/BCAST_NORM round xn along with it, for lo
(320 values) a separate step. Inject, router and PLE stay BF16. `IE_MEGA_HC_BF16=1` switches back.

| | gr.down | gr.up | Rounding lo | tok/s (decode) without reloading (2 runs) |
|---|---:|---:|---:|---:|
| BF16 | 2.51 ms | 2.30 ms | – | 41.4–41.7 |
| Q8_0 | 1.88 ms | 1.60 ms | 0.15 ms | **43.1–43.6** |

Teacher forcing, 1,363 tokens: Q8_0 perplexity 2.239 / top-1 82.4 %, BF16 2.262 / 82.0 %: no loss.
Against CPU (int8 mode): top-1 9 of 9.

Q8_0 reaches only 57 % (down) and 67 % (up) of the bandwidth here: down has 320 rows for 512 waves,
up 640 units for 512 waves (two rounds, the second a quarter full). Next step there: split K.

Did not help (discarded): IQ4_NL repacked to 16-byte nibbles + scales at the row end (microbenchmark
77 % as before, bit-identical); two units per iteration in the megakernel (+0.5 %, noise).

## Addendum: discarded

- **Splitting K** for gr.down (10240 → 320) into 2/5/10 parts and gr.up (320 → 10240) into 2/5 parts, partial sums in
  separate buffers, the next step sums them: all variants 43.1–43.6 tok/s (decode), gr.down rather slower
  (1.85 → 2.08 ms with 10 parts). The utilization of the 512 waves is not the bottleneck.
- **Fetching weights ahead of the barrier** with `s_prefetch_data` (gfx12): memory access fault at addresses
  0xffff…, also in the single test with a valid buffer in 4 of 6 runs (ROCm 10.1, LLVM 24). Not usable.

## Addendum: int8 matvec as "unpack, then B vectors"

For the verify pass of the speculation, every sub-block unpacks its weights once into 8 int8 words with scale and
offset per half of 16; after that one dot product per vector. Signs of the grid formats now via
`(g ^ m) + (m & 0x01010101)` instead of two dot products. Q2_0 (down experts in 9 layers) now on the int8 path.

- Microbenchmark old against new (B = 1, 2 runs each): IQ2_S 56–57 / 57 %, IQ3_S 77 / 78 %, IQ4_NL 73–74 / 73 %: equal.
  Q2_0 int8 64 % (float path before 29 %).
- Megakernel without reloading: **44.1–44.3 tok/s (decode)** (before 43.1–43.6), moe.down 2.21 → 1.97 ms.
- Against CPU: top-1 7 of 9 (int8 rounding now also before the Q2_0 experts), kernel itself against equally rounded x
  nearly bit-identical (≤ 7e-8).
