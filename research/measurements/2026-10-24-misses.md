# Expert misses in decode, 2026-10-24, own measurement

Coder IQ1_M, drafter DFlash, 90–91 expert slots per layer, 25.1 GB pinned, 64 GB RAM.

## What a pass costs (throughput test `--batch-bench 600`, B = 4, repeated prompt, 2 runs)

| | ms per pass |
|---|---:|
| all experts in VRAM (`IE_FAKE_EXPERTS=1`) | 34.4–34.6 |
| real (1,185 hits, 32 GPU direct, 87 CPU, 60 refilled per pass) | 42.1–42.3 |

So misses cost ~7.7 ms per pass. The expert matvec itself is not the bottleneck: with all experts in VRAM
`moe.gate_up` reads ~1.54 GB in 6.0 ms (~255 GB/s, 81 % of 315), `moe.down` ~1.06 GB in 4.9 ms (~215 GB/s, 69 %),
union ~26 experts per layer estimated from hits + misses. The earlier estimate "a quarter of the
bandwidth" was wrong.

The throughput test is misleading for preloading (repeated tokens, LRU fits too well): there `IE_PREFETCH=0` was faster,
in real decode slower.

## Dropping unimportant misses (`IE_MISS_DROP=w`, experiment, lossy)

Idea from Research Square rs-11268552 (Qwen3-Next-80B, only the snippet read): misses whose weight is below w for all
tokens of the pass are dropped; the remaining weights per token are stretched to the old sum.

Quality: teacher text (teacher-long), 1,500 tokens token by token through the decode path (B = 1):

| w | NLL | Top-1 |
|---|---:|---:|
| 0 | 2.192839 | 58.7 % |
| 0.03 | 2.191831 | 59.2 % |
| 0.06 | 2.196712 (+0.18 %) | 58.9 % |
| 0.1 | 2.214492 (+1.0 %) | 58.4 % |
| 0.15 | 2.229304 (+1.7 %) | 57.5 % |

Server, with `IE_FILL=0`, one server run each (median of 3):

## Shortening the verify pass after ECOSPEC (`IE_SPEC_CUT=1`, lossless, off)

ECOSPEC (arXiv 2607.12696) chooses the draft tree by path probability / new experts. Our draft is a
chain, and the server already chooses the width by expected tokens per time. Transferred: in every layer the cost of the
experts that only tokens from j on need (hit 12, GPU direct 15, CPU 80 µs as in the planner), extrapolated to the
remaining layers, against Σ P(acceptance) · value of a token (`IE_CUT_V_US`). If it pays off, the tokens from j on keep being computed without
experts and do not count. Output with `IE_PLAN=gpu` bit-identical.

LRU prompt, 61 tokens, drafter:

| `IE_CUT_V_US` | ms per pass | Tokens per pass | Decode tok/s |
|---|---:|---:|---:|
| off | 40.1 | 3.21 | 70.8 |
| 16,000 | 40.2 (never cut) | 3.21 | 70.7 |
| 8,000 | 36.9 (12 of 26 cut) | 2.35 | 55.9 |
| 4,000 | 32.3 | 1.36 | 36.3 |

A draft token is worth ~14 ms (pass / tokens per pass), its own experts cost only ~3 ms. Cutting does not
pay off; choosing the width before the pass covers it.

## Decaying frequency instead of LRU (`IE_EVICT=lrfu`, off)

Simulation (90 slots, without preloading): half-life 10 passes 87.5 / 89.3 % against LRU 85.1 / 87.2 % (explain / rust).
In the server with preloading no gain (rust 76.1 / 76.2 against 76.7 / 76.6, H = 4 and 25 likewise). With the preloaded ones
at the back of the list, LRU already filters similarly.

## Wait time at the mailbox and combine (all experts in VRAM, B = 4, without profiler, 2 runs each)

- `combine` (norm over the hyper-connection streams): every block computes the 16 norm sums itself, at 4 tokens one
  wave per sum with 80 loads awaited one after the other. With float4 and `#pragma unroll 4`: 2.57 → 1.26 ms per pass in the
  profile, pass 34.4–34.6 → 33.5–33.6 ms.
- `host.wait` 23 µs per layer, of which selection on the CPU 8 µs (without misses) and 19 µs (real). The choice of the
  preload candidates was done before it, but is only needed after the CPU experts: moved, selection 0.91 → 0.54 ms per
  pass, real pass 37.6 → 37.3 ms.
- Rest of the selection: mainly the softmax over 256 experts (1,024 `exp` per layer at 4 tokens). Normalizing only the top-8
  would be equivalent, but changes the rounding against cpu/ref.cpp; ~0.2 ms per pass, deferred.

Teacher NLL (decode path, 1,500 tokens) 2.192839 → 2.193553 (different summation order in the norm).

## Hyper-connection matvecs (gr.down / gr.up, ~3.5 MB int8 each, ~20 µs per step), discarded without gain

All experts in VRAM, B = 4, profile:

| Attempt | gr.down | gr.up | Pass (without profiler) |
|---|---:|---:|---:|
| State | 2.09–2.12 ms | 1.78–1.79 ms | 33.6 ms |
| aligned Q8 (type 108, 3 instead of 17 loads per sub-block; bit-identical) | 2.13 | 1.91 | 33.7 |
| short rows with 4 / 8 / 16 lanes instead of 2 | – | 1.81 / 1.83 / 1.97 | – |
| `#pragma unroll` 2 / 4 in row_q8 (all int8 matvecs) | 2.10 / 2.16 | 1.98 / 2.05 | 35.2 / 35.8 |
| fewer lanes for long rows (`IE_MEGA_LANES_MAX` 16 / 8) | 2.62 / 4.52 | 1.80 / 1.78 | – |
| without inject (timing only) | 1.87 | 1.76 | – |

Neither load instructions nor lanes nor inject are the limit. Ideal would be ~11 µs per step at 315 GB/s; the rest is the fixed
price of a step (barrier, ramp-up, stragglers) at 1,142 steps per pass. Next lever there: merging
steps.

## More slots: distribution across layers and the prefill working memory (2026-10-25)

- Unequal slots per layer (simulation on IE_ROUTE_TRACE, without preloading): adapted to the own trace +3
  percentage points of hits, on other traces +0.6–0.9, on trace3 0. Online with a ghost list per layer +0.6–1.4 and 0.
  Does not justify the rework to a shared pool (slot sizes differ per layer).
- `IE_VRAM_LOG=1`: weights and buffers 5.39 GB, of which **prefill working memory 912 MB**, checkpoint 134 MB,
  slots 81 × 98.2 MB (desktop used 2.1 GB).
- Without prefill working memory (`IE_PREFILL_CHUNK=0`) 91 instead of 81 slots: pass B = 4 39.27 / 39.12 → 38.61 / 38.72 ms
  (−0.5 ms). Borrowing the working memory from the slots as in layer-wise prefill cost ~37 ms per prefill
  for copying back (912 MB). Deferred.
