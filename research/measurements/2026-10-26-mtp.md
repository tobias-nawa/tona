# MTP head in the engine, 2026-10-26

Own measurement. ie-server, Coder IQ1_M, `--mtp mtp-Qwen3.8-Flash-Next-Q8_0.gguf`, context 16384,
`scripts/bench-set.py` (11 code, 3 text prompts, greedy, up to 400 tokens each, thinking off). Tokens per pass and
times from `IE_DRAFT_LOG` (per pass: drafts, accepted, ms verify pass, ms MTP, MTP steps).

## Structure

- Third program in the megakernel: input `[enorm(E[x]) | hnorm(h_c)]` per stream → eh_proj → QSA block with its own
  KV/indexer → MoE (512 experts, top-10, all in VRAM as Q2_0, 708 MB; routing on the GPU) → own head mixer
  → LM head of the target. h = residual of the target after the last layer.
- Entry p in the MTP KV: token at p with h at p − 1. After the verify pass, a pass catches up the accepted tokens and
  in doing so computes the bonus token whose logits give the first draft (like llama.cpp, one pass instead of two).
- Q2_0 conversion of the experts: on the CPU ~7 min (first with cache file `.q2` next to the GGUF), now on the GPU
  (`k_q8_to_q2`, one thread per 64-block, computation in float) 1.0 s without cache; fixed-depth hits code 5.27 → 5.25, text 3.01 → 3.00.

## Adaptive depth

The chain stops when even the next draft, with the same calibrated probability, no longer raises the rate
E[tokens] / (verify pass(k + 1) + catch-up + k steps). Width = best k. Calibration as on the
DFlash2 path, starting with the raw q.

| Run (decode tok/s, 14 prompts) | Code | Text |
|---|---:|---:|
| DFlash2 (measurements/2026-10-26-drafter-mtp) | 87.4 | 60.8 |
| MTP, old cost table | 84.7 | 61.9 |
| MTP, measured table, 2 runs | 85.0 / 85.5 | 64.3 / 64.9 |
| MTP + argmax on the GPU | 84.1 | 64.2 |
| MTP, head IQ4_NL | 92.1 | 63.5 |
| MTP, head Q6_K (same build) | 86.1 | 65.0 |

Note: adaptive runs generate different text depending on the widths (widths from 6 round differently), the spread between
almost identical builds is large (86.1 against 92.1). Decisions about cost are therefore made with fixed depth (same text).

## MTP entries of the prompt via GEMM in the prefill

Pieces of C/2 tokens in the phase range: embedding (CPU, pinned) → `k_mtp_in16` → eh_proj as GEMM over
token × stream → gr_attn → idx_k/k/v → `k_qsa_prep` without q and indexer q (nh = ih = 0) → ring. Before, one
megakernel pass per 8 tokens ("KV only"). Found along the way: the passes cost 750 ms per 13K prompt, not the full last
layer and not the chunk size (DFlash2 with 89 slots and MTP with chunk 5120 checked, neither had an effect).

| long (13K, 3 runs) | MTP entries | Prefill tok/s | Decode afterwards | Tokens per pass |
|---|---:|---:|---:|---:|
| megakernel passes | 747 ms | 1569 | 61.7 | 2.56–2.63 |
| GEMM | 58 ms | 1734 | 62.2 | 2.60–2.73 |
| DFlash2 | – | 1747 | 52.2 | 2.50–2.62 |

In addition, the context rows of the shortened head now come via a kernel from the LM head in VRAM (before, from the
mapping of the GGUF; hits equal, 5.27 / 3.01).
