# CPU/GPU planner for missing experts and reproducible output, 2026-10-24, own measurement

PCIe x16. ie-gpu-gen with `--mega --dflash` (85 slots like the server), context 4,096 and 8,192.

## Cause of the differing answers

- Prefill: reproducible, 8,000 tokens, 3 runs, NLL 1.010029023 in all.
- Decode (teacher, 1,500 tokens):

| Setting | NLL per run |
|---|---|
| `IE_PLAN=gpu`, without drafter | 2.188810044 ×3 |
| `IE_PLAN=gpu`, with drafter | 2.194021953 ×2 |
| Default (planner with learned CPU time) | 2.189645617 / 2.193753342 |

- The planner gives pinned misses to the CPU or the GPU, depending on which would finish earlier. It learned the CPU time
  on a sliding basis from measurements. The split therefore fluctuates, and CPU and GPU round differently (different summation order,
  silu with `__expf` on the GPU).
- With fixed costs the split is still not completely fixed: with 60 µs 1.430562438 / 1.428952899, with 80 µs in two
  runs 1.422937890 and 1.408183174. Presumably the refilling of the VRAM cache on the side: whether an expert is already
  inserted depends on timing, and thereby whether the CPU or the GPU computes it. Not measured directly.
- Only `IE_PLAN=gpu` is reproducible: hits and reads from RAM compute identically on the GPU.

## Speed of the planners (teacher, 2,000 tokens of Claude Code text, 2–4 runs each)

| Planner | tok/s (decode) |
|---|---|
| learned CPU time (previous default) | 27.0 / 27.7 |
| GPU only (`IE_PLAN=gpu`) | 28.0 / 27.7 |
| fixed 125 µs | 29.0 / 28.9 |
| fixed 100 µs | 29.1 / 30.2 |
| **fixed 80 µs (new default)** | 30.3 / 30.0 / 30.3 / 29.4 |
| fixed 60 µs | 30.5 / 30.5 |

Generation with drafter (500 tokens, English design task, 3 runs each), time per pass: learned 59.8 / 59.8 / 60.9 ms,
fixed 80 µs 59.7 / 60.3 / 58.5 ms. Code prompt: GPU only 37.9 tok/s against 37.7 mixed; English prompt: GPU only
31.9–32.4 against 34.1–34.9 mixed.

## Conclusion

- Default fixed 80 µs: faster than the learned time and less fluctuating, but not bit-exact.
- Reproducible (tests, comparisons): `IE_PLAN=gpu`, ~7 % slower on English text.
- Fully reproducible with the CPU would only work if the CPU computed bit-identically to the GPU or if refilling at the end of the pass
  were synchronous. Both open.
