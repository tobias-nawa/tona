## Expectation (with tolerance)

All numbers are unchecked unless a source is named.

- **Reference accuracy, `old-ref1`:** family A 93.1 % (557 of 598) and B 29.5 % (86 of 292) in the main run
  (`2026-10-30-threshold-main.md`; older engine). Tolerance: A +-2 pp, B +-5 pp. Source for B: f0 = 0.086 between two
  runs of the same shard (ref1 against ref2), so one run moves by about 1.7 pp per standard deviation of the paired
  difference (sqrt(f0 / n)), +-3.4 pp at 95 %; the engine changed since, hence the wider +-5 pp. A value outside is a
  finding about the engine, not about the shard.
- **Closed-book A on the old shard:** 13.5 % (81 of 600), +-2 pp.
- **New against old, same tasks:** the shards disagree token by token (KLD 0.164 on code, 0.360 on prose) and 25 % of the
  experts differ, so the flip rate is expected at the level of the damaged stages of the main run, well above the noise
  floor: f_A 0.04 to 0.10 (noise floor f0_A = 0.005; stages with KL 0.03 to 0.12 gave 0.015 to 0.064) and f_B 0.25 to
  0.40 (f0_B = 0.086; the stage with KL 0.12 gave 0.25). The sign of the accuracy difference is not predicted: the NLL
  of 2026-11-12 is equal on code and 0.023 nats better on prose, and the vendor claims a gain.
- **What n tasks can resolve:** the smallest detectable paired difference at 80 % power, alpha 0.05 is
  d = 2.8 sqrt(f / n) (research/31, section 3.4; used in the README):

| Family | n | f | d |
|---|---|---|---|
| A | 598 | 0.04 / 0.07 / 0.10 | 2.3 / 3.0 / 3.6 pp |
| B | 292 | 0.25 / 0.32 / 0.40 | 8.2 / 9.3 / 10.4 pp |
| B (floor, same shard) | 292 | 0.086 | 4.8 pp |

  Reading for the vendor claim: a gain of +3.6 pp (SWE-bench) is at the edge of what family A can resolve (d about 3 pp)
  and far below what B can resolve (d about 9 pp); B would need n = 7.84 f / d^2 = about 1,900 tasks at f = 0.32 for
  3.6 pp (A about 420, which it has). The result will therefore say "no loss larger than about 3 pp on A and about 9 pp
  on B" or name a difference that is larger than that. It cannot confirm a +3.6 pp gain on B, and A is a retrieval test
  at 93 % with little headroom, a weak stand-in for SWE-bench. The tasks are small (one function in a 62K context, reference
  accuracy 29.5 % on B because 2,000 tokens and a short analysis come before the code), unlike agentic issue repair.
- **Decision rule, fixed now:** the shard counts as "not worse on tasks" when the upper bound of the loss on A is within
  3 pp and on B within 5 pp of the Newcombe interval; the B bound is not reachable on B at n = 292 (interval half-width
  about 4.6 to 5.3 pp at f 0.25 to 0.32); B is therefore judged by its point estimate and interval and stated as
  unresolved when the interval spans more than 5 pp below zero. A loss with McNemar p < 0.05 on either family is a finding
  that blocks the switch until explained.

  `work/build/w108/`, so that no rebuild by another worker can change it during the night. Nothing is built during a run.

## Start command (tonight)

```sh
cd <worktree>
python3 tools/quiet_check.py        # before; hw_report.py output into this file
BUILD=w108 W76_PORT=8091 nohup bench/threshold/shard_run.sh > work/tmp/w76/logs/shard_run.out 2>&1 &
# afterwards, per label: python3 -I bench/threshold/analyze.py old-ref1 new-ref1 [--select FILE]
```

`shard_run.sh` takes one label as argument to run only that one, and skips labels that have a `.done` file in
`work/tmp/w76/runs/` (resume after an abort). Check before starting that `ss -ltn` shows nothing on 8091 (else
`W76_PORT=8099`) and that `work/gpu.lock` is free. Stop a run by the PID of its `tona-server`, never by name.
Selection for the secondary analysis: `python3 -I bench/threshold/select_tasks.py old-ref2 old-closed`, then
`analyze.py old-ref1 new-ref1 --select work/tmp/w76/tasks/selected-old-ref2.json`.

## Smaller selection if it does not fit

Not needed (5.7 h of 8 h). If the night is shorter than the pair (2.5 h): run family A alone (`run.py ... --families A`
in both arms, about 0.2 h each with the 600 questions) which resolves d = 2.3 to 3.6 pp, and give family B a 100-task

catches a collapse, not a difference.
