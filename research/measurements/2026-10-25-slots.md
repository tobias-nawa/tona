# More expert slots (2026-10-25)

Server `--ctx 16384`, `scripts/bench-openai.py`, 3 requests per case, median. Desktop with ~1.1 GB VRAM. State main
55ea1de (passes up to 8 tokens).

## VRAM layout (`IE_VRAM_LOG=1`)

Weights and buffers 5.43 GB (of which prefill work memory 912 MB for chunks of 2,048), checkpoint 149 MB,
slots 91 × 98.2 MB = 8.94 GB, reserve 640 MB.

## Rejected: prefill up to 2,048 tokens also layer by layer (borrow slots instead of own work memory)

`IE_PF_LAYERED_MIN=32` (otherwise from more than one chunk). Prefill in the server, 4 requests with a random line, median of the
last 3:

| Prompt | chunk by chunk | layer by layer |
|---:|---:|---:|
| 232 | 470 | 359 |
| 605 | 881 | 768 |
| 1,720 | 1,327 | 1,270 |
| 2,471 | 1,413 | 1,411 |

Layer by layer costs ~0.1–0.17 s fixed per prompt (copying the borrowed slots back, layer buffer). An agent sends a few
hundred new tokens per round: loss ~0.1 s per round against ~0.04 s gain in decode (300 tokens, +1.3 %).

Research on this (agent research, Sonnet, 2026-10-25): nothing reliable found for shared memory between the prefill buffer and the
expert cache; llama.cpp #29887 (`--moe-cache-mib`, merged) sizes the cache by free VRAM. Misses on the CPU (Fiddler,
kTransformers) are already computed by the engine.

## Expert matvecs (ie-wide-probe --exps)

Expert formats (tensors over 48 layers): gate/up IQ2_S 20, IQ3_XXS 17, IQ3_S 10, IQ4_XS 1; down IQ4_NL 39,
type 42 9. int8 path, 32 blocks × 16 waves; "large" = 128 MB per format (above the Infinity Cache), "phase" = 10 experts
(5–9 MB), 50 launches in a row.

| Format | L | large nb = 1 / 4 GB/s | phase nb = 1 / 4 µs |
|---|---:|---:|---:|
| IQ2_S (gate/up) | 8 | 148 / 69 | 39.7 / 73.2 |
| IQ3_XXS | 8 | 154 / 73 | 45.8 / 85.9 |
| IQ3_S | 8 | 188 / 81 | 44.4 / 85.9 |
| IQ4_XS | 8 | 258 / 171 | 32.6 / 53.3 |
| IQ4_NL (down) | 8 | 196 / 92 | 45.7 / 86.8 |
| IQ4_NL (down) | 4 | 217 / 159 | 36.5 / 63.1 |

- Rejected: down with 4 lanes (`IE_MEGA_LANES_EXP_SHORT`). In the pass B = 1 ±0, B = 4 −0.07, B = 8 −0.7 ms, and the
  CPU experts recompute in the order of 8 lanes (cpu/experts.cpp): no longer bit-exact.
- Rejected: signs of the grid formats via ALU instead of an LDS table (bit j by multiplication with 0x00204081 onto
  bit 8j). In the probe tool IQ2_S nb = 4 73.2 → 58.9 µs, but only because the phase sat in the Infinity Cache; in the pass
  moe.gate_up 3,131–3,135 µs against 3,131–3,135 µs (3 runs each, B = 1 and 4), bit-exact (NLL 2.487739615).
- In the pass the expert part reads at ~167 GB/s (B = 1: gate_up 3.13 + down 2.4 ms for ~0.92 GB on the GPU), the
  dense part at ~257 GB/s. A pass B = 1 reads ~5.1 GB: 16.2 ms at 315 GB/s against 25.1 ms measured.

## Upper bound for preloading into the Infinity Cache (`IE_WARM_TEST=1`)

gate_up and down per layer twice in a row; the second run reads the layer's experts (~14 and 7 MB)
warm from the Infinity Cache. Throughput test LRU prompt, profile µs per pass:

| | B = 1 cold | warm | B = 4 cold | warm |
|---|---:|---:|---:|---:|
| moe.gate_up | 3,344 | 2,591 | 7,448 | 6,982 |
| moe.down | 2,335 | 1,607 | 6,464 | 5,413 |

At most −1.5 ms per pass (B = 1 ~6 %, B = 4 ~4 %), if the preloading fell entirely into gaps. Warm, gate_up and down are
almost as slow as cold (B = 4: −6 % and −16 %): then unpacking is the brake, and there the rejected
sign computation via ALU would help (IQ2_S warm nb = 4 −20 %). Research (Sonnet, 2026-10-25): weight preloading into L2/LLC in the
megakernel found without a published measurement; gfx12 has `s_prefetch_data` (unchecked), MALL allocation per page.

## Rejected: preload blocks next to light steps

`bench/micro/prefetch.hip`: `s_prefetch_data` does not make 10 MB warm (afterwards 45.8 µs like cold 46.2), a read kernel
before it does (21.4 µs).

Not slower with 16 instead of 32 blocks (B = 1): gr.down, gr.up, combine, dn.recur, host.wait, router, dn.conv, mix,
moe.sum, moe.act, dn.norm (together ~8.5 ms per pass).

Prototype: the last 8 or 16 blocks do not compute marked steps but read the layer's predicted experts
(list from the CPU after the experts of the previous layer, top-8 per token from the router prediction) in pieces
of 32 KB; the others compute the step with fewer blocks (bit-exact, NLL 1.561826915 with and without).

| marked steps (blocks) | ms per pass B = 1 | moe.gate_up µs |
|---|---:|---:|
| none | 26.09–26.12 | 3,395–3,407 |
| combine, gr.down, gr.up, mix, router (8) | 26.72 | 2,900 |
| the same (16) | 26.75 | 2,889 |
| combine, mix (16) | 26.26 | 3,180 |
| dn.recur (16) | 26.76 | 3,315 |
| dn.recur, dn.norm, combine, mix (16) | 27.01 | 3,219 |

Preloading works (moe.gate_up up to −0.52 ms, warm upper bound −0.75), but costs more: the latency-bound
steps (gr.down/gr.up/router) get slower under the additional load, and two blocks share one
WGP: a preload block takes output clocks from the computing neighbor (dn.recur +1 ms). First version with the list on
the GPU (top-k from the prediction, slots one by one over PCIe): combine +0.8 ms.

## Smaller prefill work memory: chunks of 1,024 instead of 2,048

`IE_PREFILL_CHUNK=1024`: work memory 912 → 496 MB, slots 91 → 95. Prompts longer than one chunk go layer by layer.

Decode +0.3–0.5 %, but prompts with 1,025–2,048 new tokens +0.05 s. An agent round with ~1,500 new tokens
and 300 output tokens thus loses ~0.025 s. Parked. Extra slots in the work memory (a second slot region)
would have the same catch: every prefill up to 2,048 tokens clears them.
