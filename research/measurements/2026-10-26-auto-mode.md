# Auto-mode checker: intermediate checkpoint before the fixed tail

Own measurement, 2026-10-26.

## Finding in real operation (test project, Claude Code in auto mode, 15:55–15:58)

Before every `Bash` call a check request: ~42K tokens of prompt, thinking off, 7–8 tokens of answer. Only
30,531 tokens were reused (checkpoint at the start of the last message), each time 10,955–12,015 tokens were recomputed in
8.4–9.1 s. In 3 min ~100 s of 190 s. The main conversation, by contrast: 0.4–1.5 s prefill, 2–12 s decode.

Cause: the checker sends rules, then the log of the actions, then the same question in one message; new
actions come before the question. The state of the DeltaNet layers cannot be rewound, only a checkpoint saved
before the divergence is reusable.

## Change

If a prompt deviates from a saved one at least 1,024 tokens after the reusable part, the rest of the saved one
(at most 8,192 tokens) counts as a fixed tail; 16 tokens before it an intermediate checkpoint is saved (RAM only). A longer one
replaces it, an ordinary end of a conversation does not.

## Replica (`automode.py`: 30K rules, 10K log, +78 tokens per round, alternating with a main conversation)

| Check request | before (as in operation) | after |
|---|---|---|
| 1. | everything, 23.3 s | everything, 23.3 s |
| 2. | 9,706 new, 6.6 s | 9,706 new, 6.6 s, saves the checkpoint |
| from 3. | ~9,700 + 78 per round new, 6.6 s and more | **126–1,152 new, 0.5–1.6 s** |

The checkpoint moves as soon as 1,024 tokens are lost (round 16 in the replica). Main conversation unchanged 0.5 s.
