# KV cache int8 and KV in RAM, 2026-10-23

Commit ef8dc3d: K and V int8 symmetric, scale (float) per 32 values, row per position 1,152 B per QSA layer
(13.8 KB per token over 12 layers); raw indexer key now only as a ring over 16 positions; pool unchanged f32.
From 1 GiB total KV the cache lives in pinned RAM (hipHostMalloc Mapped|NonCoherent), IE_KV_HOST=0/1 forces it.
64 GB RAM, 25.1 GB experts pinned.

## KV in RAM: correctness and cost

- Perplexity 3000 tokens, IE_PLAN=gpu (all misses GPU-direct, deterministic), --slots 96: VRAM and RAM each
  twice exactly NLL 1.4814. Without IE_PLAN the NLL varies in the 4th digit, because CPU and GPU compute experts
  not bit-identically and the split depends on run times.
- Decode after 7,454 tokens of prompt (Claude Code recording), 300 tokens, IE_PLAN=gpu, same output:
  VRAM 87.6 ms per pass (25.8 tok/s decode), RAM 94.0 ms (24.2 tok/s decode): **−6 %**.

## Open

tokens per pass 2.52 instead of 3.5–3.8). Candidates: attention kernel (one block per token and head over up to 2,048
cells), indexer and top-k over all pool blocks, worse drafts at long context.
