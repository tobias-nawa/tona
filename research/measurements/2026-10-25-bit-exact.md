# 2026-10-25: experts bit-exact on CPU and GPU

Own measurement. 64 GB RAM, desktop on the same GPU. Teacher text `teacher-long.txt` through the decode path
(`ie-gpu-gen --mega --teacher`, B = 1), passes with `pass.sh` (B = 4, 600 tokens, with drafter).

## What changed

- **CPU kernel in the order of `row_q8`** (8 lanes per row, like the expert groups in the megakernel): lane j sums
  the sub-blocks j, j + 8, … with `s = fma(d_x, r, s)`, `r = fma(s_hi, hi, s_lo · lo)`, then the xor tree 4, 2, 1.
  Per 8 sub-blocks: 4 × vpdpbusd, folded in integers onto the 16-halves (unpack/add, exact), scales per 8
  sub-blocks as a vector from the block bytes.
- **GPU:** `apply_q8` with an explicit fma (before, the compiler's contraction decided the order).
- **Activation:** shared `det::exp` (`cpu/detmath.h`, Cody-Waite + Cephes polynomial, ~1 ulp), on the CPU
  as an AVX-512 version with the same steps.
- **`moe.sum` in fixed point (2^-36, int64):** the sum no longer depends on the order; the CPU also delivers its
  partial sum as int64.
- `ie-expert-check` (ctest `expert_bitexact`): silu over 1 million values, int8 rounding and matvec of all 6
  expert formats, CPU against GPU: bit-exact.

Debugging: a shadow comparison in the pass (the CPU recomputes the GPU experts) first showed deviations in almost

0 deviations in all 48 layers.

## Width of the check pass: what it depends on

`ie-gpu-gen --mega --batch-check N` with `IE_BATCH_NB=k` (passes of exactly k, all accepted) and
`IE_BATCH_REF_NB=r` (comparison against passes of r instead of single steps), bitwise per position:

| | equal | first deviation |
|---|---:|---|
| 4 against 4 (second run) | 64/64 | – |
| 4 against 2 | 0/64 | position 0 |
| 4 against 1 | 0/64 | position 0 |

Even token 0 of a pass depends on the width. Two places split their sums by nb: the hyper-connection norm
(`wpc = MWAVES / (nb · hc)` waves per sum) and the pieces of the split-K attention
(`att_chunk(n_cells, nb, …)`). Both tried with BMAX instead of nb: afterwards token 0 is equal (4 against 2: positions
0, 1 equal), tokens 1–3 still deviate. Cost: B = 1 23.22 → 23.44 ms per pass, B = 4 unchanged.

The rest is DeltaNet: single steps commit the state token by token (S ← α S + δ kᵀ), a pass with
several tokens computes the later ones in closed form from S0 and the dot products k_i·k_b, and committing
m tokens combines the α (S ← (Π α) S + Σ G_i δ_i k_iᵀ). Mathematically equal, rounded differently. Under
speculation the same token ends up at position 0 or 2 of a pass depending on acceptance, hence not repeatable. The remedy
would be a canonical computation (advance the state per token in registers, or pieces at fixed absolute
positions); both are a rebuild of the hottest kernel. The two small changes were therefore removed again while
DeltaNet is open. Quality: see above, unaffected.

## Preloading no longer evicts predicted experts (`IE_PRE_KEEP`, default on)

Preloading took the LRU tail without protection: if an expert sat there that the router of the next layer had just
predicted (already in the cache), it was evicted for another predicted one. Now all experts predicted for l + 1
(top-16 per token) that are already loaded are in the protection list of `take_slot`. Idea from
arXiv 2511.05814 (agent research).

Server, `bench-openai.py` csv, rust, explain, 3 requests each, median, 2 server runs:

| Decode tok/s | off (`IE_PRE_KEEP=0`) | on |
|---|---:|---:|
| csv | 90.3 / 90.3 | 91.1 / 91.1 |
| rust | 78.6 / 78.6 | 79.3 / 79.4 |
| explain | 61.6 / 61.6 | 62.2 / 62.3 |

The two server runs are almost equal: with bit-exactness, server measurements are repeatable too, and small
gains become visible.

## DeltaNet canonical: check pass bit-exact across the width

`op_dn_recur` now computes token by token: each lane holds its rows of the column in registers, first commit the m
accepted tokens of the previous pass (S ← α S + k δᵀ, fmaf), then per new token
S_{b−1}ᵀk_b (4 partial sums per lane, then xor over the lanes of the column), δ_b, S_b, o_b = S_bᵀq_b. Before: closed
form from S0 and the dot products k_i·k_b. Prefill commits open decode tokens in the same order. In addition
`att_chunk`/`att_chunk_blk` and the hyper-connection norm with BMAX instead of nb.

The first version with 16 columns per wave: 64 rows per lane, spilled (scratch k_mega<4> 200 → 480 bytes per lane),
server pass rust 41.0 → 42.6 ms. With 8 columns (`IE_DN_CW`, 32 rows per lane): scratch 248 bytes.
