# OEA: fewer experts in passes of several conversations (stage 4)

Own measurement, 2026-10-26. OEA after arXiv 2511.02237 (research in papers.md): each token keeps its best k0
of the 10 experts, fills the remaining places in its ranking only from the union of the top-k0 of all tokens of the
pass, weights renormalized over the chosen ones. Only in passes of several conversations (`IE_OEA_K0`); one conversation
alone stays unchanged.

## Quality: −log p of the next token (teacher forcing, `ie-gpu-gen --multi-check`)

Two conversations in separate slots, passes of 8 tokens (1–7 per conversation, `IE_MULTI_NB=7`), partly rejected; the
accepted rows are counted. "alone" = each conversation in its own passes (without OEA). Smaller is better.

Run 1: A = C++ (engine/gpu/mega.hip), B = Python (scripts/*.py), 1,199 tokens each:

| k0 | experts per layer | A | B |
|---|---:|---:|---:|
| alone | | 2.1868 | 1.4041 |
| off (together) | 45.2 | 2.1829 | 1.3939 |
| 8 | 37.3 | 2.1890 | 1.4157 |
| 7 | 33.3 | 2.1836 | 1.3980 |
| 6 | 29.2 | 2.1876 | 1.4072 |
| 5 | 24.9 | 2.2137 | 1.4166 |

Noise: "alone" against "together without OEA" already differs by 0.004 / 0.010 (passes of 6 or more tokens round
differently, k_wide). k0 = 8 is worse than 7 in this run, so noise of this size.

## Real tasks: 23 programming tasks with tests (`scripts/bench-effort.py`, medium, greedy)

Two clients at the same time (tasks in reverse order), so almost only shared passes; one run per k0.

| k0 | client a | client b | together | time a / b | failed |
|---|---:|---:|---:|---:|---|
| off | 21/23 | 21/23 | 42/46 | 994 / 873 s | roman, csv (both clients) |
| 7 | 22/23 | 23/23 | 45/46 | 792 / 843 s | roman (a) |

No loss visible. roman and csv are the borderline cases that flip from run to run even without OEA; 46 tasks
show only coarse differences (1–2 points stay invisible). Shell code (the case with +0.025) is not included.

## Conclusion

- OEA saves 26–35 % of the distinct experts and brings +5–7 % tokens per ms in shared passes.
- The quality does not hold everywhere: in run 2 even k0 = 7 costs +0.025 per token on shell code (~5 times the
  noise of ~0.005), k0 = 6 +0.028; in run 1, 7 and 6 stayed within the noise, 5 was clearly above.
- Decision by the quality rule (\"Code quality has to be right. Otherwise the speed is worth nothing.\"): **off**
  (`IE_OEA_K0=0`), included as an option for measurements.
- Open for later: milder variants that only swap places with a small weight (threshold on p instead of a fixed k0),
  and XShare per conversation (draft tokens of the same conversation share more experts anyway).

## Protocol for the variants (fixed before the run, 2026-10-26 evening)

After the research on statistics (llama.cpp PR #5076, arXiv 2407.09141, 2411.00640): teacher forcing over
10,000 tokens each (A: C++ from engine/server, B: justfile and all scripts/*.sh), two conversations in passes of 8.
Per token −log p alone and together, KL(alone || together), top-1 (`IE_MULTI_DUMP`, `scripts/nll-compare.py`).
Reference: together without OEA, computed twice (repeatability). For each variant the paired difference of −log p
against the reference on the same tokens, 95 % interval by block bootstrap (blocks of 64 tokens, 4,000 draws).

**Rule "within noise":** the interval contains 0 and its upper bound is below 0.01 nats per token, for A and B;
in addition the KL divergence must not rise markedly (report the interval of ΔKL). The 23 tasks then only show
that nothing is grossly broken (with 46 runs, 2–3 points cannot be shown).

## Result of the variants (9,999 tokens each, `/var/tmp/claude/oea-dumps`)

Reference computed twice: bit-exact (no run noise). Scatter per token 0.275; the 95 % interval of a mean
is thus about ±0.007–0.009, the detection limit is at ~0.01 (as estimated in the research).

Even without OEA: together against alone KL 0.026–0.028, top-1 equal 93.9–94.6 %, −log p unchanged (−0.002 / −0.001).
That is the different computation of wide passes (k_wide, f16 instead of int8 from 6 tokens); which is closer to the full model
is open (comparison against cpu/ref.cpp follows).

| Variant | −log p against reference A (C++) | B (shell) | ΔKL A / B | top-1 A / B | experts per layer | Rule |
|---|---|---|---|---|---:|---|
| k0 = 7 | +0.0009 [−0.0084, +0.0099] | +0.0080 [−0.0007, +0.0165] | +0.048 / +0.046 | 90.7 / 90.1 % | 33.5 | ✗ |
| k0 = 7, HITS | −0.0073 [−0.0149, 0.0000] | −0.0001 [−0.0080, +0.0073] | +0.017 / +0.019 | 92.6 / 92.5 % | 41.7 | ✓ |
| k0 = 7, EXTRA = 8 | −0.0017 [−0.0083, +0.0046] | +0.0023 [−0.0043, +0.0088] | +0.011 / +0.012 | 93.4 / 93.0 % | 41.4 | ✓ |
| k0 = 7, HITS + EXTRA = 8 | −0.0032 [−0.0086, +0.0023] | −0.0026 [−0.0070, +0.0020] | +0.001 / +0.000 | 93.9 / 94.0 % | 45.7 | ✓ (saves nothing) |
| k0 = 8, HITS | −0.0060 [−0.0125, +0.0003] | +0.0007 [−0.0059, +0.0071] | +0.011 / +0.013 | 93.0 / 92.8 % | 42.8 | ✓ |

(Reference: top-1 93.9 / 94.6 %, 45.9 experts.) Plain k0 = 7 fails (shell up to +0.017, KL almost tripled).
With protection of the experts in VRAM or with additional experts by total weight (XShare), −log p stays within the noise;
but the KL divergence rises measurably (+0.011 to +0.019, intervals exclude 0), which is 40–70 % of what the
f16 computation of wide passes accounts for.

## Large test (2026-10-27 night): tasks and speed, two conversations at the same time

23 tasks per client, two clients (reverse order), greedy, `bench-effort.py medium`. Speed:
`bench-parallel.py` 2 clients, two rounds alternating (the card was warm after an hour of load, so the reference is
85–86 instead of 90 tok/s; all variants under the same conditions).

| Variant | Tasks | failed | accepted per ms (shared passes) | Decode total |
|---|---:|---|---:|---:|
| reference (off) | 43/46 | csv, lru, roman | 0.095 / 0.096 | 85.6 / 86.3 tok/s |
| k0 = 7, EXTRA = 8 | 43/46 | csv, expr, roman | 0.099 / 0.099 (+3.6 %) | 88.3 / 86.0 |
| k0 = 7, HITS | 42/46 | csv, expr, roman, weekday | 0.103 / 0.104 (+8 %) | 90.2 / 92.4 |
| k0 = 8, HITS | 43/46 | lru, roman, semver | 0.101 / 0.099 (+4.7 %) | 90.5 / 87.8 |

Tasks: no loss visible, the differences are below the fluctuation of the reference itself (42 and 43/46 in
two runs); roman and csv flip in almost every run. The test only rules out gross failures.

## Conclusion (state 2026-10-27)

- Best candidate: **k0 = 7 with HITS** (swap only experts that are not in VRAM): +8 % in shared
  passes, −log p within noise (A −0.007, B −0.000), tasks like the reference. Price: KL +0.018 (the distribution
  shifts measurably, top-1 equal 92.5 instead of 94 %).
- Milder: k0 = 7 with EXTRA = 8 (+3.6 %, KL +0.012) or k0 = 8 with HITS (+4.7 %, KL +0.012).
- Plain k0 = 7 is out.
- Default stays off until the maintainer decides; as an option in the TUI.

## Decision 2026-10-27: on

Decision: it is within noise, so on. Default now `IE_OEA_K0=7` with HITS (`IE_OEA_HITS=0` switches the protection off,
`IE_OEA_K0=0` OEA entirely). Check with the new build (engine-b45), alternating:

| | Run 1 | Run 2 |
|---|---:|---:|
| one conversation (bench-set), default | code 86.6, text 63.0 tok/s decode, same tokens as before (3,139 / 1,148) | – |
| 2 clients, `IE_OEA_K0=0` | 0.095 accepted per ms, 85.6 tok/s total | 0.100, 90.7 |
| 2 clients, default | 0.103, 90.0 tok/s | 0.104, 94.5 |

+4–8 % accepted tokens per ms in shared passes; the range comes from the clock of the card (run 1 warm).
