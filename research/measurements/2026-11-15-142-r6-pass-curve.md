# R6 core generalization: pass curve against the baseline (check C4 of the multi-architecture design), 2026-11-15

RX 9060 XT (gfx1200), Zen 5. Branch `142-r6-core` (0627d9d) against `work/build/base` (R0, main 64a8204).

## Plan (written before the first run)

**Question.** Did R6 (per-layer expert layout in `Mega`, prefetch, selection and prefill MoE; mailbox stride as a named
constant; prefill sequence behind an interface) move the time of a pass or the logits? R6 touches `mega_prefetch.cpp`,
`mega_select.cpp`, `mega_experts.cpp`, `prefill_run.cpp` and `prefill_moe_run.cpp`, which are on the hot-path list of check C4.

**Scope.** `tona-gpu-gen --mega --batch-bench 600`, big model (plain GGUF, no profile, no drafter), widths 1, 4 and 8
(one per kernel instantiation), 2 repeats per width inside a run, 3 runs per arm, arms interleaved (base, R6, base, ...),
all in one hold of the GPU lock. 6 runs, about 1 to 2 minutes each plus model load.

**Expectation.** Logits hashes (`TONA_BENCH_HASH=1`) equal in every run of both arms at every width: C1 (machine code of all 217
kernels identical) and the host changes only index differently, so the same values reach the kernel. Time per pass within the
spread of the base arm itself (6 values per width: 3 runs x 2 repeats); no earlier figure is cited, because the spread is
read from this run. A median of the R6 arm outside that spread is a finding: the cost is then in the host path of the touched
files and gets fixed before merge.

**Active tooling.** `TONA_BENCH_HASH=1`, `TONA_BENCH_WIDTHS=1,4,8`, `TONA_BENCH_REPEAT=2`, `OMP_NUM_THREADS=6`; no profiler, no other TONA_* variable.
The server is not involved. No build ran during the runs: they sit behind `scripts/gpu_queue.py`.

## Result

`tona-gpu-gen --mega --batch-bench 600`, ms per pass (decode-shaped verify pass of W tokens, no prefill), median over 3 runs x 2 repeats,
arms interleaved, raw output in `work/` of the run (`/var/tmp/claude/r4/c4/`):

| Arm | W1 | W4 | W8 |
|---|---|---|---|
| base (main 64a8204) | 22.96 (22.90 to 23.09) | 32.58 (32.57 to 32.61) | 47.07 (47.00 to 47.38) |
| R6 (0627d9d) | 22.98 (22.94 to 23.35) | 32.63 (32.55 to 32.68) | 47.07 (47.02 to 47.44) |
| R6 against base | +0.09 % | +0.17 % | +0.00 % |

Logits hashes: fb383dddbe844f17 at W1 and W4, f24a81b74654b9ef at W8, in all 6 runs of both arms (equal).
Reading against the plan: hashes equal as expected; the medians differ by at most 0.05 ms, inside the range of the base arm at W1
(0.19 ms) and within 0.04 ms of the base maximum at W4. No finding.
