### Scope

- Code: `gpu/arch/nemotron_h/{program,blocks,buffers,kernel,prefill_layer}` (+ headers), `gpu/prefill_kvstore.{hip,h}` (K and V of a chunk into the int8 cache, Bolt's attention has no RoPE), the registry entry (`ArchSupport` with types F32, Q8_0, IQ2_XXS, NVFP4, tier 2), the kernel profile (`max_experts = MEGA_MAX_EXPERTS_WIDE`, `ExtraQuants::kNvfp4Iq2xxs`), `tools/tona_bolt_layers.cpp`.
- Shared files (own commit after step 0): `model/model_base.h` (`n_blocks`, `moe_block`, `moe_ordinal`, `has_kv`: the trunk as the prefill and the state code walk it, defaults identical to what they computed), `gpu/prefill_run.cpp`, `prefill_moe_run.cpp`, `mega_state.cpp`, `mega_build_bufs.cpp` (descriptors per block, 88, not per MoE ordinal), `mega_build.cpp` (registries), `prefill_run.h` (`phase_bytes` takes the model).
- Runs, every one through `scripts/gpu_queue.py`: builds as `cpu` jobs; unit tests; `isa-diff`; `tona-bolt-layers` and the llama.cpp / Tona logit dumps as `gpu` jobs merged into as few queue jobs as the questions allow; one server start.
- Not in scope: evals, model comparisons, `ab.py` measurements, the DFlash drafter (B8).

### Expectation (with tolerance and source)

- Step 0: identical everywhere (source: the move changes host code only; C1 of the same tree was identical).
- N2c: deviation per block below 0.05 of the largest value of the residual at widths 1 and 8 (source: the Ornith oracle comparison, mean |d nll| 0.12 to 0.17 with 4-bit weights; the oracle does not quantize activations, the engine does, and deeper blocks accumulate it; the tolerance is a first guess and is reported with the numbers, not tuned afterwards). The scale tensors of block 0 are printed; the check is meaningful only if they differ from 1.
- N7: top-1 equal in at least 90 % of the 64 steps per prompt, mean KL below 0.02 (source: Ornith 96.9 to 100 %, KL 0.0055; Bolt has two lossy formats more, IQ2_XXS experts and NVFP4, and llama.cpp quantizes the activations of these types differently, see the B1 mini-model rows).
- Speed: decode about 3 to 8 tok/s with the experts streaming from RAM over PCIe (source: 4.82 GB per token at 315 GB/s is the all-in-VRAM ceiling of 65 passes/s, 17 GB of experts do not fit 16 GB VRAM next to 4.4 GB dense; the misses cost 1.2 MB each at about 25 GB/s; unverified). Prefill: the Mamba-2 layers alone allow about 8,900 tok/s (B4), the GEMMs about 5,000 tok/s; the first number will be much lower because experts stream per group (Ornith 1.6 to 3.5 k tok/s). Tolerance: a factor of 3 either way; outside that is a finding.

`TONA_BOLT_TAP=1` for N2c only. `TONA_DETERMINISTIC=1` for the identity checks. `TONA_PF_DEBUG=1` for the prefill lines. No profiler, no other `TONA_*` variable.

### Stop rules

- A check stops when its question is answered: N2c stops at the first block above the tolerance (the printout lists all blocks of the run; localization starts there), a golden stops at its first difference.
- Jobs are looked at every 15 minutes at most. Exit 75 (desktop guard): requeue the same job and note it. An out-of-memory or a GPU fault stops everything and goes to the maintainer.
- One build directory. Test servers on port 8094 only, never 8662; processes are stopped by PID.

## Prior art

Change type: `backend` for the module, `refactor` for step 0 (proof: `isa-diff` of all 415 kernels identical, Coder goldens and Ornith prefill logits identical, `TONA_DETERMINISTIC=1`).

- llama.cpp b11822 `src/models/nemotron-h.cpp`, `nemotron-h-moe.cpp`, `mamba-base.cpp` (pinned checkout `work/src/llama.cpp`), status: read by B1 to B5. One graph builder per architecture over a generic op set with a runtime interpreter; the layer kind per block comes from the per-layer arrays, the recurrent state lives next to the KV cache. Adopted: the block semantics (already in the oracle). Not adopted: the generic graph; ours is a typed program for a kernel that holds only Bolt's op families, with the experts streamed per MoE ordinal.
- vLLM `NemotronHForCausalLM` (hybrid KV and state manager, from memory, not opened for this ticket): Mamba state next to attention KV as cache groups. Not adopted: paged state; fixed slots and the replay commit of the design (3.4) instead.
- [Nemotron 3, arXiv 2512.20856](https://arxiv.org/abs/2512.20856), status: read (B1, B5). LatentMoE; many small experts make the slot count, not the width of one expert, the limit.
- [Layered prefill, arXiv 2510.08055](https://arxiv.org/abs/2510.08055) and [MoE-CORE, arXiv 2610.01950](https://arxiv.org/abs/2610.01950), status: tested (Ornith O6). Adopted: the driver's layer-major sweep with the next layer's experts copied during the running one; for Bolt the buffers go by the ordinal among the MoE blocks, so the copy of the next MoE layer overlaps the Mamba-2 and attention blocks between two MoE blocks too.

Search: tools/papers/scan.py was not run afresh for this ticket (the earlier Bolt tickets read `research/papers.md` and the pinned sources); `research/papers.md` was read for "nemotron" and "mamba" (SketchSSM, LinearKV, Nemotron 3.5 Super/Lightning titles only); topics v1: moe-offload, linear-attention; window 12 months. A fresh scan is an open item before the pull request text.
